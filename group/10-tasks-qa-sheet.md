# The QA session — the run sheet

**Four passes over the same 46 tasks. One question per pass.** About an hour.

## The rule that makes it work: one question at a time

**Do not go row by row.** A row asks three different questions at once, so you switch between them 46 times and
your standard drifts — the instrument measuring consistency ends up inconsistent itself.

**Go down a column instead.** Hold one question, answer it 46 times, then pick up the next. Three context
switches instead of 138, and each pass is internally calibrated because one standard is applied in one sitting.

## How to answer

- **Pick from the list. Never write prose.** Fixed words are comparable; sentences are not, and prose is where
  the consistency goes.
- **First instinct.** If a row takes more than a few seconds, mark it `?` and move on. A row that needs
  discussion is telling you the task as written isn't one real thing — that is an answer, not a delay.
- **No discussion during a pass.** Disagreement gets marked, not resolved. Resolve after the pass, in one go.
- **If more than one person answers: answer independently, compare afterwards.** Two people giving different
  answers for the same task is not a problem to iron out — **it is the finding.** It means the task varies by
  who does it, which is pass 1's answer arriving from a different direction.

**Its own pass, deliberately.** Asked during passes 1–3 it becomes an interruption and gets skipped; tacked on
at the end it gets rushed. It is the only pass that can find what the other three cannot.

# Reading the result

**After all four passes, not during.**

| Pattern | What it means | What follows |
|---|---|---|
| **`from scratch` · `remembered` · `nowhere`** | Done well and lost every time — rebuilt from zero next month by whoever is around | **The build list.** Highest value regardless of automation verdict |
| **anything · anything · `nowhere`** | The work evaporates | `record` first. It is the cheapest primitive and does not need the task automated to pay |
| **`varies`** anywhere | A habit, not a process | Nothing can be automated until there is a shape. Decide the shape before building anything |
| **`standard` · `a system` · `a system`** | Already handled | Skip it, and skip every work item beneath it |
| **`?`** | The row isn't one real thing | Split it or strike it. Do not build against it |
| **Two people disagreeing** | The task varies by person | Pass 1's answer, arriving from a different direction |

**Then the other two registers resolve by block.** A work item in `11-work-items.md` beneath a task reading
`standard / a system / a system` needs nothing built. A row in `backlog.md` mapping to no surviving task is
struck as a group, unread — which is how 115 unreviewed rows get resolved without anyone reading 115 rows.
