# Backlog — every action in the repo, in one register

*Why this file exists, in a sentence: the strategy is settled but its actions were scattered as prose across
the plan, the open items and nine group documents — this register extracts them into one working surface so a
planned process can run from it. It adds nothing: no new positions, no re-argued decisions, no invented owners
or dates. Every row traces to its source. `NEXT.md` keeps the reasoning and the sequencing logic; `decided.md`
keeps what is closed; this file is the one that is allowed to change constantly.*

## How to read it

**Not everything here is a project, and the Type column is doing real work.** A lot of what has felt
unactionable turns out to be decisions and lookups dressed as projects:

- **Do** — work that takes time.
- **Decide** — a choice only a named person can make. Minutes, once it is put in front of the right person.
- **Fetch** — a fact to look up or a query to run. No judgement required.

**Status:** `ready` (nothing blocks it) · `in progress` · `blocked` (named blocker) · `done` (kept for the
record) · `parked` (deliberately not now — a choice, not debt).

**Owners are named only where the repo names them.** A `—` means unowned, and that is information rather than
a gap to fill by guessing — the US thread appears on the stress test precisely because it had no owner.

**When an item completes:** mark it done here, land any evidence in `decided.md`, and do not pass back through
`group/`. The ratchet applies to this file too.

**IDs are stable and rows are regular** so the register can be lifted into engine or any tracker when the
process gets a system home. Until then, this file is the system.
